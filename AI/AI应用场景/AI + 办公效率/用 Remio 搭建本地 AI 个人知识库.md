## 用 Remio 搭建本地 AI 个人知识库

很多人第一次搭个人知识库，都会从「把 PDF 扔给 AI」开始。

这个方法适合临时读一两篇文章，但资料一多就会遇到几个问题：

- 文件散在桌面、下载目录、微信、邮箱、飞书、浏览器收藏里，很难统一检索
- 每次问 AI 都要重新上传文件，慢，而且浪费 token
- 录音、视频、图片、网页、聊天记录这些资料，普通文件夹搜索基本搜不到
- Agent 做任务时经常用 `grep`、`find` 扫目录，结果又慢又容易漏

如果你的目标不是「临时问一个 PDF」，而是长期维护自己的工作记忆、项目资料、会议记录、客户信息和学习笔记，可以试试本地优先的 AI 个人知识库工具：[Remio](https://remio.ai/)。

它的核心思路不是再造一个网盘，而是先把你已有的资料解析成可检索的本地索引和向量，再让 AI 按需取相关上下文。

## 适合什么场景？

Remio 更适合这些场景：

1. 资料格式很杂  
   比如 PDF、Word、PPT、Excel、网页、录音、视频、图片、邮件、消息、普通笔记混在一起。

2. 想保留本地资料结构  
   不想把所有内容重新搬进一个在线文档系统，只希望 AI 能理解已有资料。

3. 经常让 AI 帮你做总结和查找  
   比如整理会议纪要、回忆某个客户说过什么、找某份资料里的关键结论。

4. 使用 AI Agent 做事  
   Agent 可以通过 Remio CLI / skill 调用 Remio 已经建立好的本地索引，而不是每次都扫目录、读整份文件。

## 第一步：安装 Remio

打开 Remio 官网：

https://remio.ai/

安装桌面客户端后，先把常用资料目录加入同步范围，比如：

- 桌面
- 下载目录
- 项目资料文件夹
- 会议录音目录
- 微信或其他 IM 工具的文件目录

Remio 会在本地解析这些资料，建立索引和向量。

这里的重点是：后续问 AI 时，不需要每次把整份资料塞进 prompt，而是先检索出相关片段，再把更小、更准的上下文交给模型。

## 第二步：把资料按来源接进去

建议从最常用的 3 类资料开始：

### 1. 文档资料

把 PDF、Word、PPT、Excel、Markdown、CSV 等文件所在目录加入 Remio。

适合问：

- 这份方案里提到的关键风险是什么？
- 某个客户之前的报价是多少？
- 这些研究资料里有没有提到类似案例？
- 帮我找和「续费」「流失」「知识库」相关的所有材料

### 2. 录音和视频

会议录音、访谈录音、课程视频这类资料，普通搜索基本没法用。

Remio 可以把音视频转成文本后再检索，适合问：

- 上次访谈里用户最大的痛点是什么？
- 会议里谁承诺了下周交付？
- 这段培训视频讲了哪些步骤？

### 3. 网页和笔记

如果你平时收藏了很多网页、教程、文章，Remio 可以把网页内容转成更干净的文本再索引。

适合问：

- 我之前收藏过哪些关于 RAG 的文章？
- 哪篇文章提到过本地向量库？
- 帮我总结最近看过的 AI Agent 资料

## 第三步：用问题驱动检索

知识库真正有用，不是因为资料多，而是因为能在合适的时候找出来。

可以从这类问题开始：

```text
帮我找一下最近和某个项目相关的资料，并按时间线整理。
```

```text
根据我本地资料，总结某个客户最关心的 3 个问题。
```

```text
找出所有提到「会议总结」「录音转写」「知识库」的资料，按来源分类。
```

```text
根据已有笔记，整理一份产品周报草稿。
```

如果你用的是 Claude Code、Codex 这类 Agent，也可以让 Agent 通过 Remio 的 CLI / skill 先查 Remio，再继续写文档、改代码或整理报告。

需要注意：Remio CLI / skill 是 Remio 桌面客户端的接口，不是独立知识库服务。没有安装和运行 Remio 客户端时，Agent 不能凭空读取 Remio 索引。

## 和直接上传文件给 AI 有什么区别？

直接上传文件适合一次性任务，Remio 更适合长期资料管理。

| 方式 | 适合场景 | 问题 |
| --- | --- | --- |
| 直接上传文件 | 临时阅读单个 PDF、Word | 每次都要上传，资料一多就乱 |
| 文件夹搜索 / grep | 找明确关键词 | 找不到语义相关内容，音视频和图片基本无能为力 |
| 普通知识库 | 团队文档、手动整理 | 需要迁移资料，格式支持有限 |
| Remio | 本地个人资料、跨格式检索、Agent 调用上下文 | 需要先安装桌面客户端并建立索引 |

## 一个实用工作流

可以把 Remio 当成「个人上下文层」：

1. 平时正常保存资料，不强迫自己换工作习惯
2. Remio 在本地解析文件、网页、录音、邮件、消息、图片和笔记
3. 需要写东西或做决策时，先用 Remio 找相关上下文
4. 再让 AI 根据检索结果生成总结、方案、周报、访谈纪要或任务清单

这样做的好处是：AI 不需要每次从零开始，也不需要读取一堆无关文件，能更快拿到与你当前问题相关的内容。

## 小结

如果你只是偶尔问一个 PDF，普通 AI 对话工具就够了。

如果你的资料长期散落在本地文件、网页、会议录音、邮件、聊天记录和笔记里，并且希望 AI 或 Agent 能持续调用这些个人上下文，Remio 这类本地优先知识库会更合适。

它解决的不是「再建一个文档系统」，而是让已有资料先变成可检索的本地记忆，再把相关上下文交给 AI 使用。
