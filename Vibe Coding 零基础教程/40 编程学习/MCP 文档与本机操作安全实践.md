# 用 MCP 给 AI 编程补充版本文档，并安全执行本机任务

> 社区投稿：分别用文档检索型 MCP 和电脑操作型 MCP，理解「让 AI 查资料」与「让 AI 操作电脑」的权限差异。

你可能遇到过这种情况：AI 写出来的代码看起来没问题，运行时却发现某个 SDK 方法已经改名。更麻烦的是，当 AI 能直接操作电脑后，一次错误命令可能真的改动项目文件。

MCP（Model Context Protocol）把外部能力提供给 AI 客户端，但不同 MCP 服务的权限差异很大。本文用两个实际项目做例子，介绍如何把「先验证文档」和「再检查本机」拆成两步。

## 一、先让 AI 查正确版本的官方文档

想象一个任务：项目用的是特定版本的 Next.js，但 AI 按另一个版本的缓存规则写代码。直接问「Next.js 缓存怎么用」，很容易得到混合多个版本的答案。

更稳妥的提问方式是：

> 请先确认我项目实际使用的依赖版本，再查对应版本的官方文档。每个关键结论都附来源链接；如果没有对应版本的文档，请明确说明。

这里可以使用 Context7、Docsy 等文档型 MCP。它们解决的是「查什么、从哪里查」的问题，而不是替你修改电脑。

以社区维护的 Docsy 为例，它提供 5 个只读工具，可以解析库 ID、查看版本、查询带来源链接的文档、搜索以及按索引读取结果。

在 Claude Code 中连接：

```bash
claude mcp add --transport http docsy https://docsy.remcp.site/mcp/registry
```

之后按照客户端提示完成账号登录。注意：Docsy 远程 MCP 使用 OAuth 2.1。没有登录时收到 HTTP 401 是正常的认证响应，不等于服务故障。

接下来试着问：

> 查找 React useEffect 清理副作用的官方说明，附原始文档地址。请不要把其他版本的行为当作当前版本。

有个细节要特别注意：**发现一个版本标签，不等于该版本的文档已经被收录。** 如果工具没有准确版本的内容，应当回到发布者的官方文档核对，而不是让模型猜答案。

## 二、再让 AI 检查本机，但不要默认开放全部权限

当你需要 AI 查看 Git 状态、读日志或运行现有测试时，就涉及另一种 MCP：电脑或开发环境工具。

例如，ReMCP 允许用户把自己的 Windows、macOS 或 Linux 电脑明确配对到账号，然后通过经过授权的 MCP 客户端使用设备上的文件、进程、终端以及部分桌面功能。

对于 macOS 或 Linux，安装了符合要求的 Node.js 后，可以从产品页面获得配对命令；当前公共客户端提供：

```bash
npx --yes @remcp/remcp@latest connect
```

设备配对需要由用户确认。之后支持远程 OAuth MCP 的客户端可以连接到：

```text
https://remcp.site/mcp
```

在开始使用前，别忘了区分：

- **读操作：**列出目录、读取指定文件、查看进程、获取诊断信息。
- **写操作：**修改或删除文件、启动进程、执行终端命令、点击桌面按钮。
- **权限边界：**MCP 账号登录、设备配对和操作系统权限不是同一回事。配对电脑并不会让 AI 自动拥有管理员权限。

初次连接时，建议先给 AI 一个保守任务：

> 只读取项目 Git 状态和测试配置，告诉我计划运行哪些命令。执行会修改文件的操作前，必须先征求同意。

ReMCP 0.2.194 增加了在终端显示配对二维码的能力，但扫码仍然进入需要用户明确批准的配对流程，不能将二维码理解为免密码自动授权。

## 三、给 AI 编程建立一个简单的安全工作流

1. 先读 `package.json`、锁文件或构建配置，确认实际依赖版本。
2. 使用文档型 MCP 查询该版本的官方说明，并保留来源 URL。
3. 在动手修改前，让 AI 列出准备修改的文件和要执行的命令。
4. 测试优先在非生产环境完成；执行写操作前明确确认范围。
5. 最后检查 `git diff`、测试报告与日志，确保结果与目标一致。

MCP 的价值不是「给 AI 无限权限」，而是**让每个外部能力都有明确的来源和边界**。当检索、执行、验证分开进行时，遇到错误也更容易定位。
